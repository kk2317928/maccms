# MACCMS v10 AI 內容處理與 Headless API 二次開發設計

日期：2026-09-18  
狀態：待使用者審閱  
基線：`magicblack/maccms10` `master`（實作前鎖定確切 commit）

## 1. 目標與範圍

以全新安裝的 MACCMS v10 作為內容管理後端，第一階段只處理影片（Video），建立：

- AI 自動整理片名、多語翻譯、分類與標籤映射。
- 重名偵測、重複影片候選、可復原合併。
- TMDB 搜尋、配對與資料補全。
- 整合於 MACCMS 原後台的智能內容工作台。
- 供未來獨立 Next.js 前端使用的完整 `/api/v1` Headless API。
- 沿用 MACCMS 會員資料的安全 Token 認證、收藏、觀看進度與排行。
- 移除 MACCMS 官方非必要更新、公告、聯盟或統計通訊。

第一階段不建立 Next.js 前端，不將文章、漫畫或圖片納入 AI/TMDB 管線，也不要求 Redis、Docker 或常駐 Worker。

## 2. 已確認決策

| 項目 | 決策 |

| 前端方向 | 未來使用獨立 Next.js；本階段只交付後端、後台及 API |
| 安裝方式 | 全新 MACCMS 安裝 |
| 內容範圍 | 只處理影片 |
| 處理方式 | 半自動：AI → 查重 → TMDB → 人工審核 → 發布 |

| 重複處理 | 管理員確認後合併；副本留存合併指向與復原紀錄 |
| 後台 | 整合 MACCMS 原有後台與權限系統 |
| 執行環境 | 一般 Linux／寶塔面板，MySQL 佇列 + Cron |
| API 範圍 | 完整內容、會員、收藏、觀看、推薦與排行 API |
| 官方通訊 | 停用所有非必要官方連線，保留管理員主動設定的業務服務 |

## 3. 架構

採用「核心相容 + 擴充層」方案。保留 MACCMS/ThinkPHP 核心、原生採集、影片管理、會員及權限；AI、TMDB、查重、任務與 API 放在界線清楚的擴充模組中。只在採集完成、影片儲存及發布等必要位置接入事件，避免把新邏輯散落於原控制器。

處理流程：

1. MACCMS 採集或匯入 API 寫入原始影片。
2. 建立具冪等鍵的背景任務。
3. AI 整理、翻譯及詞典映射。
4. 產生重複候選並等待必要的人工決策。
5. 搜尋及匹配 TMDB，保留候選與分數。
6. 管理員最終審核後發布。
7. `/api/v1` 只輸出已發布且允許公開的資料。

目前上游已包含 API、任務、多語內容、統計及 AI 外掛相關結構。實作前需盤點並優先重用安全且符合需求的部分；本設計中的表名是職責名稱，若上游已有等價表，應以擴充既有表為先，不平行建立重複系統。

## 4. 資料模型

### 4.1 原生影片表

`mac_vod` 繼續作為相容主表，保留 `vod_name`、`vod_en`、`vod_sub`、演員、導演、地區、分類、標籤、圖片、審核狀態及 `vod_play_*` 播放欄位。原生採集器和影片編輯頁不得因擴充功能失效。

### 4.2 影片擴充資料

新增或擴充一對一影片擴充表，至少包含：

- 唯一六位 `public_id`；使用無混淆字元集，碰撞時重試，建立唯一索引。
- `title_tw`、`title_cn`、`title_en`、`original_title`、`old_titles`。
- `type2`：如電影、韓劇、日劇、美劇、台劇、短劇等第二層類型。
- `tmdb_id`、`tmdb_type`。
- `trailer_url`、`preview_url`。
- `old_poster`、`old_poster_s3`、`poster_s3`。
- `workflow_status` 與 AI、TMDB、查重完成時間。
- `merged_into_vod_id`、`published_at`。

`public_id` 是 API 與未來 Next.js 路由的外部識別碼；資料庫內部關聯仍使用 `vod_id`。

### 4.3 多語內容

重用上游 `mac_content_lang` 或等價結構保存可翻譯的片名、簡介和內容。影片擴充表中的固定多語片名用於高頻搜尋與排序，完整多語內容由多語表承載。缺失語言依後台設定的 fallback 順序返回。

### 4.4 詞典與關聯

以詞典及多對多關聯保存 `region`、`genre`、`tag`。詞典包含繁中、簡中、英文名稱、slug、同義詞、狀態與排序。AI 只能映射既有詞或提出待審核詞，不得直接無限制建立分類。發布確認後同步生成原生 `vod_area`、`vod_class`、`vod_tag` 字串以維持相容。

### 4.5 任務與審計

需要下列職責的資料結構；可重用現有 `mac_task`、`mac_task_log`、AI 結果與管理員審計表：

- 內容任務及每次執行紀錄。
- AI 結果、模型、Prompt 版本、用量與結構驗證狀態。
- TMDB 候選、評分、查詢條件及人工選擇。
- 重複候選、判斷特徵與人工結論。
- 合併前快照、搬移項目及復原紀錄。
- 匯入來源、外部識別碼、原始 payload 指紋與結果。

大型原始回應和錯誤紀錄不放入 `mac_vod`。API Key 加密保存，日誌必須遮蔽秘密。

### 4.6 播放來源與集數

第一版以原生 `vod_play_from`、`vod_play_url`、`vod_play_server`、`vod_play_note` 為相容資料源，建立單一解析／序列化服務，輸出 `source -> episodes[]` 結構。採集、匯入、合併及 API 必須共用此服務。

第一版不拆成逐集資料表。若未來需要逐集統計、上下架或內容權限，再以版本化遷移轉為正規化資料表。

### 4.7 狀態分離

`workflow_status` 表示 `imported`、`ai_processing`、`duplicate_review`、`tmdb_matching`、`manual_review`、`published`、`rejected`、`failed`、`merged`。原生 `vod_status` 繼續表示 MACCMS 發布審核狀態，兩者不得混用。

## 5. AI 處理

AI 輸入包括原始片名、年份、地區、分類、簡介、演員與導演。輸出必須符合 JSON Schema，包含：

- 清除廣告詞、畫質、集數等無關前後綴後的片名。
- 原始片名、繁中、簡中、英文候選片名及別名。
- 內容類型、年份和 TMDB 搜尋線索。
- 地區、類型、標籤的詞典映射。
- 信心分數與簡短判斷理由。

結構驗證失敗時有限次重試；仍失敗則進入人工處理，不寫入正式欄位。後台可設定 Base URL、API Key、模型、逾時、重試、批量、Prompt 版本與每日預算。每個結果保存模型及 Prompt 版本，確保可追溯。

## 6. 重名、查重與合併

重名只表示片名相同；重複表示同一作品。候選依下列證據計分：

1. 相同 TMDB ID。
2. 正規化原始片名 + 年份 + 媒體類型。
3. 多語片名／別名 + 年份。
4. 片名 + 主要演員／導演。
5. 片名相近但年份未知。

系統不得自動合併。後台並排顯示片名、年份、類型、地區、演職員、海報、播放來源、分數及理由。管理員選擇主影片後：

- 合併播放來源和集數並按 URL 去重。
- 保留別名、舊片名、來源和外部識別碼。
- 副本標記 `merged` 並指向主影片，不立即實體刪除。
- API 查到副本 `public_id` 時返回 canonical 主影片資訊。
- 保存合併前快照，允許受權管理員復原。

## 7. TMDB 配對與補全

搜尋順序為原始片名、英文片名、繁／簡片名、別名；優先帶年份，必要時加入演員或導演。候選評分同時考慮片名、年份、電影／電視類型、地區和演職員。

- 唯一高信心候選可預選，但仍進入最終人工審核。
- 多個接近候選由管理員選擇。
- 無可靠候選標記為無匹配，不強行寫入。
- 支援手動輸入 TMDB ID 重新抓取。

可補全多語片名、原始片名、簡介、年份、上映日期、地區、類型、演職員、海報、背景圖、預告、評分及外部 ID。TMDB 缺少某語言譯名時才使用 AI 候選；仍不可靠則留空。

欄位來源保存為 `import`、`ai`、`tmdb` 或 `manual`，預設優先級為 `manual > confirmed_tmdb > ai > import`。人工欄位自動鎖定，背景任務不可覆蓋，除非管理員明確解除或在差異預覽中批准。

## 8. 後台管理

新增「智能內容」一級選單：

- 工作台：各狀態數量、用量、失敗率、Cron 心跳與積壓警告。
- 待處理列表：篩選、批次入隊、暫停、重試、略過、鎖定和查看紀錄。
- AI 審核：原值／建議值並排，支援逐欄接受、修改、拒絕及鎖定。
- 重複審核：候選並排、選擇主影片、合併、復原及標記不同作品。
- TMDB 配對：候選預覽、手動 ID、無匹配與重新搜尋。
- 最終審核：必填檢查、多語／圖片／播放預覽、發布、退回或草稿。
- 設定：AI、TMDB、查重權重、Cron、匯入 API、公開 API、CORS、快取及外部連線。

批次操作只建立任務，不在 HTTP 頁面請求中等待外部 API。

權限至少拆分為查看、執行 AI/TMDB、審核、合併／復原、發布及安全設定。合併、復原、批量覆蓋和金鑰修改需二次確認並寫入審計。

## 9. 任務佇列與 Cron

使用 MySQL 任務佇列和短時 CLI Cron，預設每分鐘執行。任務包含類型、payload、狀態、優先級、嘗試次數、下次執行時間、鎖擁有者、鎖逾時、冪等鍵和錯誤摘要。

- 以原子領取避免兩個 Cron 同時處理同一任務。
- 程序中斷後，逾時鎖可安全回收。
- 指數退避並限制最大重試次數。
- 每次 Cron 限制任務數和總執行時間。
- 每階段獨立重跑；修改片名、年份或類型只失效受影響階段。
- 未來可換成常駐 Worker，但服務接口與任務格式不變。

## 10. Headless API v1

### 10.1 公開內容

- `GET /api/v1/home`
- `GET /api/v1/videos`
- `GET /api/v1/videos/{public_id}`
- `GET /api/v1/videos/{public_id}/episodes`
- `GET /api/v1/search`
- `GET /api/v1/taxonomies`
- `GET /api/v1/videos/{public_id}/recommendations`
- `GET /api/v1/rankings`
- `GET /api/v1/people/{slug}`
- `GET /api/v1/site-config`

API 使用明確 DTO 白名單，不直接序列化資料庫記錄。只返回已發布影片。`locale` 支援 `zh-TW`、`zh-CN`、`en` 及可設定降級順序。OpenAPI 文件為交付物。

### 10.2 認證與會員

沿用 MACCMS 會員資料，但另建前端 API 認證層：短效 Access Token、輪換式 Refresh Token、Refresh Token 雜湊保存、裝置工作階段、撤銷及登入紀錄。前端 Token 不可進入管理後台。舊密碼在成功登入後可逐步升級雜湊。

### 10.3 收藏與觀看

提供收藏增刪、列表、最近觀看、集數、來源、進度秒數、總時長及跨裝置續播。Next.js 未登入時可使用 localStorage；登入後以更新時間合併，不以空資料覆蓋伺服器進度。

### 10.4 推薦、統計與排行

事件包括播放開始、有效觀看、進度、完播與收藏。匿名裝置或會員事件按時間窗口去重，生成今日、7 日、30 日和總榜。第一版推薦使用類型、地區、標籤、演職員、熱門度及新鮮度規則，不引入向量資料庫。

### 10.5 播放安全與快取

播放端點只返回允許的來源，移除內部備註，支援來源停用與可選短效簽名網址。拒絕 `javascript:`、本機檔案、內網和不允許網域。

公開內容支援 ETag、條件請求和 HTTP 快取；發布或修改時精準失效。登入、搜尋、進度、事件和匯入端點各自限流。CORS 只允許設定的 Next.js 網域。匯入 API 和公開 API 使用不同憑證與權限。

## 11. 官方通訊與出站管控

實作前建立出站端點清單，掃描 PHP、外掛、模板、JavaScript 及預設設定。移除或停用：

- 版本檢查、更新提示、遠端更新下載與執行。
- 官方遠端公告。
- 官方聯盟預載／緩衝頁面及相關預設 URL。
- 非必要統計或其他回傳。
- 後台官方更新入口和不可達路由。

保留管理員主動設定的採集、AI、TMDB、S3、SMTP、SMS 等服務。保留 Apache 2.0 授權和必要原作者聲明。

外部 URL 共用 SSRF 防護：預設 HTTPS、阻擋 localhost／私網／link-local／metadata、DNS 解析檢查、重新導向後重驗、回應大小與逾時限制、網域白名單及秘密遮蔽。後台提供可審計的外部連線清單和最後呼叫時間。

## 12. 部署與遷移

主要驗收環境為 Nginx、PHP 8.1、MySQL 5.7/8.0，並包含 curl、mbstring、openssl、pdo_mysql、json、fileinfo。上游宣告 PHP >= 7.0，但新增功能不以已停止安全維護的舊版本作主要目標；正式實作前以鎖定 commit 跑 PHP 相容測試。

資料庫使用版本化、可重複執行的遷移命令和遷移紀錄；不在一般 Web 請求中自動改表。部署前備份資料庫與設定，高風險遷移提供回退方法或不可逆警告。

移除官方更新後，更新流程改為自己的 Git 發布：上游合併到測試分支、差異審查、測試、版本標籤、備份、短暫維護、更新、遷移、快取清除、健康檢查及失敗回退。

## 13. 錯誤處理與可觀測性

- 對使用者返回穩定錯誤碼，不暴露堆疊、SQL、Key 或外部原始回應。
- 每個工作流程階段記錄開始、完成、耗時、重試與錯誤分類。
- 工作台監控佇列深度、最舊任務年齡、成功率、外部限流及 Cron 心跳。
- 所有管理員覆蓋、合併、復原、發布及安全設定變更可追溯。
- 日誌設定保存期限，Token、密碼、Cookie 和 API Key 永不明文落盤。

## 14. 測試與驗收

至少涵蓋：

- 原生採集與新匯入 API。
- 播放來源／集數解析和無損重新序列化。
- AI JSON 驗證、失敗重試、Prompt 版本與欄位鎖。
- 重名不誤合併、候選評分、合併、canonical 指向及復原。
- TMDB 唯一、多候選、無匹配及手動 ID。
- Cron 併發鎖、超時回收、重試與冪等。
- 會員登入、Token 輪換、重放防護、撤銷及權限隔離。
- 收藏、觀看同步、事件去重、推薦及四種排行。
- API DTO、分頁、locale fallback、CORS、限流與快取失效。
- SSRF、SQL 注入、XSS、惡意播放 URL 和敏感資料洩漏。
- 禁止 MACCMS 官方非必要出站請求。
- MACCMS 原生影片管理、採集及會員功能回歸。

交付物包括安裝／更新文件、環境設定範例、Cron 指令、資料庫結構、OpenAPI 規格、測試報告及人工驗收清單。
